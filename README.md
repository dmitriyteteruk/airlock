# airlock — счётчик бульков гидрозатвора

Приложение для Raspberry Pi 3 + USB-веб-камеры, которое смотрит на гидрозатвор бродильной
ёмкости и считает каждый «бульк» — проход пузырька CO₂. Работает без монитора (headless):
результат виден в веб-интерфейсе по локальной сети, события пишутся в журнал на SD-карте.

```
камера → ROI (зона гидрозатвора) → вычитание фона → сигнал движения → детектор пиков → счётчик
```

## Что умеет

- Считает бульки **независимо по каждой зоне** (до 12 гидрозатворов на одном кадре): статистика,
  темп и пороги — свои для каждой зоны, ничего не суммируется между зонами.
- На карточке каждой зоны — статус **«Брожение»** и темп «в час» за последние 60 минут (из истории,
  поэтому после перезапуска сервиса не обнуляются). Пороги статуса:

  | Статус | Условие |
  |---|---|
  | Отсутствует | < 1 булька за 24 часа |
  | Очень медленное | 1–24 булька за 24 часа |
  | Медленное | 1–30 в час |
  | Среднее | 31–60 в час |
  | Быстрое | 61–360 в час |
  | Очень быстрое | > 360 в час |
- График активности по зонам (столбики уложены по зонам с легендой) с диапазонами от 1 часа до
  60 дней и живым графиком «сырого» сигнала движения для выбранной зоны. История переживает
  перезапуск: при старте график подтягивается из журнала `events.jsonl`, длинные окна
  автоматически прореживаются (минуты → часы → сутки).
- Счётчики и история переживают перезагрузку Pi: итоги в `data/state.json`, а «в час» и график
  догружаются из журнала `data/events.jsonl` при старте.
- Журнал каждого события с временем, амплитудой и длительностью (`data/events.jsonl`, экспорт в CSV).
- Тревога «брожение встало», если бульков нет дольше заданного времени.
- Защита от ложных срабатываний: засветка всего кадра, толчок камеры, автоэкспозиция.
- Веб-интерфейс: видео с рамками зон, редактор зон мышью, подбор порогов, журнал.

## Требования

- Raspberry Pi 3 (или Zero 2 W / Pi 4) с Raspberry Pi OS Bookworm или Bullseye, Python 3.9+.
- USB-веб-камера (UVC). Хватит любой 640×480; выше разрешение не нужно и только грузит CPU.
- Гидрозатвор в кадре должен быть хорошо освещён и неподвижен относительно камеры.

## Быстрая установка

```bash
git clone <репозиторий> ~/airlock-src && cd ~/airlock-src
sudo bash deploy/install.sh
```

Скрипт поставит системные пакеты (`python3-opencv` и т.д. — они уже собраны под armv7l,
компиляции не будет), разложит приложение в `/opt/airlock`, создаст virtualenv, зарегистрирует
systemd-сервис `airlock` и запустит его. В конце выведет адрес веб-интерфейса.

Полезные флаги:

```bash
sudo bash deploy/install.sh --dir ~/airlock   # поставить в домашний каталог
sudo bash deploy/install.sh --no-service      # только зависимости, без systemd
```

Ручная установка без скрипта:

```bash
sudo apt install python3-opencv python3-numpy python3-flask python3-yaml v4l-utils
python3 -m airlock run
```

## Первый запуск и настройка

1. Откройте `http://<ip-pi>:8080`.
2. Перейдите на вкладку **«Настройка зон»**, дождитесь снимка и протяните рамку вокруг
   гидрозатвора. Чем плотнее рамка, тем выше чувствительность и меньше ложных срабатываний.
   Нажмите **«Сохранить и запустить подсчёт»**.
3. На вкладке **«Обзор»** появится видео с рамкой и счётчик. Первые ~3 секунды идёт прогрев
   модели фона — в это время события не считаются (это нормально).
4. Если счётчик молчит при реальном брожении или, наоборот, считает в пустоте — вкладка
   **«Пороги»**: кнопка **«Подобрать автоматически»** предложит пороги по накопленной статистике
   шума и пиков, затем **«Применить и сохранить»**.

Всё, что вы меняете в интерфейсе, сохраняется в `data/overrides.json` и переживает перезапуск.
`config.yaml` при этом не трогается (и не теряет комментарии).

## Командная строка

```bash
python3 -m airlock run                        # запуск: подсчёт + веб-интерфейс
python3 -m airlock run --no-web               # только подсчёт, вывод в лог
python3 -m airlock run --port 9000 --token s3cret
python3 -m airlock run --public-port 8081     # + публичная страница только для чтения на 8081
python3 -m airlock doctor                     # диагностика: список камер, кадр, проверка зон
python3 -m airlock doctor --seconds 10        # + понаблюдать 10 с и показать пик сигнала
python3 -m airlock snapshot --out shot.jpg    # сохранить один кадр
python3 -m airlock calibrate --seconds 60 --apply   # записать сигнал и сохранить пороги
python3 -m airlock events --limit 50          # последние события из журнала
```

Общие флаги (`--config`, `--data-dir`, `--device`, `-v`, `--log-level`) принимаются и до,
и после имени подкоманды.

`calibrate` — главный инструмент первичной настройки: оставьте камеру в покое на минуту
естественного брожения, и команда покажет уровень шума, амплитуду пиков и рекомендуемые
`on_threshold` / `off_threshold`, а с `--apply` сразу сохранит их.

## Веб-интерфейс

| Вкладка | Назначение |
|---|---|
| Обзор | видео с рамками зон + **построчная карточка по каждой зоне наверху**: статус «Брожение» (по суткам и темпу в час), бульков в час за последний час, последний бульк, бар сигнала; состояние системы |
| Графики | живой сигнал движения выбранной зоны с линиями порогов + гистограмма активности, уложенная **по зонам** с легендой; диапазоны 1 ч…60 дней с автопрореживанием, история подтягивается после перезапуска |
| Настройка зон | снимок кадра, рисование рамок мышью/пальцем, таблица координат, сохранение |
| Камера | разрешение, режим и значение экспозиции, яркость, автофокус и ручной фокус — со слайдерами по реальным диапазонам камеры; «Применить» показывает кадр сразу, «Сохранить» пишет в конфиг |
| Пороги | выбор зоны (или базовые для всех), свои пороги и override-статус каждой зоны, таблица автоподбора **по зонам** |
| Журнал | последние события и выгрузка CSV |

При запуске сервиса камера опрашивается через `v4l2-ctl --list-ctrls` (пакет `v4l-utils`) —
поддерживаемые контролы и их диапазоны пишутся в лог и используются на вкладке «Камера».
Если `v4l2-ctl` недоступен, берутся типовые диапазоны.

Статистика нигде не смешивает зоны: наверху, в графиках и в автоподборе каждая зона — отдельно.
Суммарного счётчика «по всем зонам» в интерфейсе нет.

Доступ по умолчанию открыт всей локальной сети. Если это нежелательно, задайте `web.token` —
тогда интерфейс спросит токен при первом открытии и сохранит его в браузере.

### Публичная страница (только просмотр)

Для внешних наблюдателей есть read-only страница: карточки всех зон (статус «Брожение»,
«Бульков в час», последний бульк), живое видео с камеры и суточный график активности.
Управление, настройки и журнал на ней недоступны.

- На основном порту: `http://<pi>:8080/public` — открыта даже при заданном `web.token`
  (эндпоинты `/public/*` намеренно без авторизации и не отдают пороги/настройки).
- Отдельным портом (чистый изолированный доступ наружу): `web.public_port: 8081` в конфиге
  или `python3 -m airlock run --public-port 8081`. Тогда на `http://<pi>:8081/` работает
  только публичная страница — админ-API там отсутствует в принципе.

```bash
python3 -m airlock run --public-port 8081
```

## Как считается бульк

Для каждой зоны кадр переводится в градации серого, из него вычитается модель фона
(MOG2 по умолчанию), маска чистится медианным фильтром, и считается **доля изменившихся
пикселей зоны** — это сигнал движения `motion(t)`. Один проход пузырька даёт один «горб»
на этом сигнале. Детектор считает горбы с гистерезисом:

- `on_threshold` — сигнал выше → горб начался;
- `off_threshold` / `drop_ratio` — сигнал упал → горб закончился, событие засчитано;
- `min_off_frames`, `min_peak_frames` — защита от одиночных шумовых кадров;
- `refractory_s` — минимальная пауза между событиями (не считать один бульк дважды);
- `max_hump_s` — принудительно закрыть затянувшееся событие;
- `saturate_ratio` — если «двигается» больше половины зоны, это засветка или толчок, а не
  бульк: событие не считается, зона уходит в короткую заморозку.

Пороги выражены в **долях площади зоны**, поэтому не зависят от разрешения камеры, но зависят
от того, насколько плотно вы обвели гидрозатвор.

### Пороги по каждой зоне отдельно

Глобальный блок `detector` задаёт значения по умолчанию для всех зон. У любой зоны можно переопределить
свои пороги — в веб-интерфейсе (вкладка «Пороги» → выбрать зону → «Применить») или в конфиге:

```yaml
rois:
  - name: airlock-2
    x: 420
    y: 130
    w: 110
    h: 170
    detector:
      on_threshold: 0.006     # только для этой зоны
```

Зона с переопределением помечена бейджем `override`. «Подобрать по зонам» считает пороги для каждой
зоны независимо и ничего не усредняет; «снять override» возвращает зону к базовым значениям.

## Настройка под свою камеру

Всё в `config.yaml` (или через веб-интерфейс). Ключи `camera.controls` принимаются и в коротких
именах, и в именах из `v4l2-ctl --list-ctrls` (`exposure_time_absolute`, `focus_absolute`,
`white_balance_automatic`, `backlight_compensation` и т.д.). Порядок важен: сначала отключаем
автоматику (`auto_exposure`, `autofocus`), потом задаём значения. Типичный набор:

```yaml
camera:
  controls:
    auto_exposure: 1   # 1 = Manual Mode — иначе экспозиция «дышит» = ложные бульки
    autofocus: 0       # 0 = выключить автофокус — его перефокусировка = движение
    exposure: 2        # выдержка; у многих UVC шаг грубый (см. ниже) — это верхний/нижний предел
    brightness: 150    # плавный регулятор уровня (главная ручка, если экспозиция слишком «ступенчатая»)
    contrast: 5
    saturation: 100
    sharpness: 20
    auto_white_balance: 0
    white_balance: 4250        # К, при выключенном авто-ББ
    backlight_compensation: 0  # 0..10 — помогает, если в кадре яркое окно/небо
    focus: 5           # ручная резкость; ДИАПАЗОН СВОЙ У КАЖДОЙ КАМЕРЫ (у некоторых 0..16, не 0..255)
```

Диапазоны смотрите в `v4l2-ctl -d /dev/video0 --list-ctrls`. Частая ловушка: у некоторых камер
`exposure_time_absolute` в самом низу меняет свет вдвое за один шаг (например, «2 — темно,
3 — пересвет», а промежуточного нет). Тогда держите минимальное не-выбитое значение экспозиции
и доводите уровень плавно через `brightness`. Если сцена с широким динамическим диапазоном
(гидрозатвор в тени на фоне окна) — подсветите сам гидрозатвор, это и снизит шум, и уберёт пересвет.

vision:
  background: mog2     # mog2 устойчив к дрейфу света; mean легче для CPU
  process_scale: 1.0   # 0.5 — вдвое меньше пикселей в анализе, экономит CPU на Pi 3

detector:
  on_threshold: 0.004  # главный порог; подбирается через calibrate / веб-интерфейс
  off_threshold: 0.0012
  refractory_s: 0.12

pipeline:
  process_fps: 20      # 20 к/с хватает: бульк длится 0.1–0.3 с

alerts:
  stall_minutes: 30    # тревога, если бульков нет 30 минут (0 = выключено)
```

### Если считает лишнее

- Убедитесь, что автоэкспозиция/автобаланс/автофокус выключены (`camera.controls`) — это причина № 1.
- Сузьте рамку зоны до самого гидрозатвора.
- Поднимите `on_threshold` и `min_peak_frames` до 2.
- Уменьшите `mog2_threshold` не нужно — наоборот, увеличьте его (менее чувствительно).

### Если пропускает бульки

- Кадр расфокусирован после отключения автофокуса — выставьте `focus` вручную (гидрозатвор должен быть резким).
- Опустите `on_threshold` (ориентируйтесь на статистику «Пики» на вкладке «Пороги»: порог должен
  лежать заметно ниже медианы пиков и выше p99 шума).
- Уменьшите `refractory_s` при очень бурном брожении.
- Добавьте света на гидрозатвор или включите `vision.equalize: true`.

## Файлы данных

| Файл | Содержимое |
|---|---|
| `data/events.jsonl` | по строке на событие: id, зона, время, амплитуда, длительность, тип |
| `data/state.json` | суммарные счётчики и id — восстанавливаются после перезапуска |
| `data/overrides.json` | настройки и зоны, сохранённые из веб-интерфейса |
| `data/snapshots/` | кадры событий, только при `storage.snapshots: true` |

Запись на SD-карту буферизуется (`storage.flush_interval_s`), чтобы беречь карту.
Кнопка «Сбросить счётчики» очищает всё: счётчики, график и журнал `events.jsonl` — чтобы после
перезапуска история не «вернулась» из журнала.

## Управление сервисом

```bash
sudo systemctl status airlock
sudo systemctl restart airlock
journalctl -u airlock -f          # живой лог, включая каждый бульк
```

## Производительность на Pi 3

При 640×480, `process_fps: 20`, одной зоне и `stream_fps: 5` приложение занимает около
10–20 % одного-двух ядер и ~150 МБ ОЗУ. Рекомендации:

- не поднимайте разрешение выше 640×480 без необходимости;
- `vision.process_scale: 0.5` почти вдвое снижает нагрузку анализа;
- `web.stream_fps: 5` и `web.stream_scale: 0.8` — поток считается только когда открыт браузер;
- OpenCV принудительно однопоточен (`OPENCV_FOR_THREADS_NUM=1` в systemd-юните), чтобы не
  дёргать планировщик на четырёх ядрах.

## Диагностика

```bash
python3 -m airlock doctor
```

покажет список `/dev/video*`, фактический режим камеры, сохранит контрольный кадр в
`data/doctor.jpg`, проверит, попадают ли зоны в кадр, и понаблюдает за сигналом несколько секунд.

Частые ситуации:

- **«Камера не отвечает»** — проверьте `ls /dev/video*`, попробуйте `--device 1`.
- **Кадр тёмный/пересвеченный** — подберите `camera.controls.exposure`.
- **Счётчик стоит на «прогреве»** — зона слишком большая или кадр меняется целиком; сузьте зону.

независимая статистика и автоподбор по зонам, корректная остановка сервера и авторизация.

## Структура

```
airlock/
  camera.py     захват V4L2 в отдельном потоке, переподключение
  vision.py     модель фона, ROI, сигнал движения, отрисовка, JPEG
  detector.py   чистая логика: пики, гистерезис, темп, timeline, подбор порогов
  pipeline.py   связка камера → ROI → детектор → хранилище
  store.py      журнал событий, персистентность счётчиков, снимки
  web.py        Flask: API, MJPEG-поток, авторизация, публичные read-only маршруты
  cli.py        run / doctor / snapshot / calibrate / events
  static/       веб-интерфейс + публичная страница public.html/public.js (офлайн, без внешних зависимостей)
config.yaml     конфигурация с комментариями
deploy/         install.sh и systemd-юнит
tests/          юнит- и интеграционные тесты
```
